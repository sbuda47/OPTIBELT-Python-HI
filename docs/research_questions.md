# Technical question register

Each question retains evidence, decisions and limitations. Current status includes the first fitted Python model and its fixed operating-group evaluation.

| ID | Questions | Current evidence / remaining work |
|---|---|---|
| Q01 | Which recordings, motors, capacities, loads, faults and severities were actually used? Do paper descriptions agree? | 41 hashed inputs; 23 normal and 18 fault-labelled recordings. Source-defined capacities and filename metadata retained. Physical motor and run identity unresolved. |
| Q02 | How were channels aligned, invalid samples handled and unusable regions removed? Could cleaning remove fault evidence? | Native channel rates and NaN storage padding established. Seven missing vibration channels found. New loader rejects native gaps; hardware offsets and safe repair policies remain open. |
| Q03 | Were sampling, anti-aliasing, window length and overlap correct? | Original factor-four downsampling is inconsistent with mixed native rates. New 32/125 current resampling tested on synthetic signals. Windows remain inside a recording. |
| Q04 | What are every feature's formula, units, channel, filter, FFT and harmonic/sideband definitions? | candidate_v1 defines 60 features with formulas and analytic tests. Physical units/calibration and harmonic/envelope features remain open. |
| Q05 | Why were features retained? Did fault/test data influence selection? How many are needed? | Training-only fixed exclusions, numerical variance floor and deterministic absolute-correlation pruning are implemented. Selected counts vary by fold; no fault/test-driven feature selection. Sensitivity work remains open. |
| Q06 | What defined healthy? Which operating states and capacities belong in its baseline? | Healthy-only roles remain enforced. Investigation identifies cross-capacity/load reference mismatch: round 4 fits only 3 HP data and tests 5 HP/0%. Supported operating envelope and representative independent healthy coverage need revision. |
| Q07 | How were features scaled and covariance regularized? What are rank, conditioning and inverse tolerance? | Equal-recording weighted standardization and covariance; fixed 0.1 shrinkage to identity; Cholesky scoring. Rank/eigenvalues/conditioning and retained columns saved per model. Diagonal baseline compared; covariance benefit not established. |
| Q08 | Which population sets HI normalization? What does clipping conceal? Was zero-load treatment consistent? | Separate equal-recording healthy 99th-percentile calibration; H=100/(1+(d/q)^2), 50 at threshold. Raw distance retained without clipping. HI is not physical health percentage or lifetime. |
| Q09 | Where does load information come from? How are thresholds calibrated, boundaries handled and unknown loads treated? | Filename load is grouping metadata, not an online measurement. Global per-fold calibration does not transfer across all capacity/load groups. Future operating-aware calibration must define deployment metadata and report unsupported conditions. |
| Q10 | Why these smoothing parameters? What are look-ahead, delay, reset and missed-fault consequences? | Fixed-threshold diagnostic: EWMA reduces healthy alarm occupancy 17.4% to 14.5%, but increases persistent records 3 to 4; the lower EWMA threshold yields 33.7% occupancy and 7 records. Separate calibration and event-level objectives matter. No settings changed. |
| Q11 | Are training, calibration and tests independent? Are overlapping windows or acquisitions shared? | Five capacity/load-group folds frozen before extraction; each primary recording is evaluated once. No random window split. Prior exposure, unknown motor/run identity and operating shift documented. |
| Q12 | Are detection and false alarms evaluated at the same threshold? How do imbalance and small samples affect uncertainty? | Window quantiles do not guarantee a recording-level event rate. Removing one of 2–3 calibration records changes a threshold by up to 32.1%. Need explicit monitoring-duration/event target and more independent episodes; no new validation claimed. |
| Q13 | Which features cause healthy alarms? Are they transients, faults in the baseline, missing sensors or valid variation? | Exact signed distance and conditional-feature diagnostics identify operating-sensitive current/vibration measures. Joint covariance amplifies some normal deviations. Six raw records pass targeted structural screens; boundary exclusion retains alerts. Physical cause remains unproven. |
| Q14 | Does fusion improve on single-sensor alarms and established multivariate methods? | Fusion, vibration, current, torque and diagonal baselines evaluated under identical roles/calibration rules. Fusion benefit over simpler baselines is not established; full tradeoffs saved. |
| Q15 | What stages run on the device/dashboard? What are end-to-end delay, memory, power and numerical tolerances? | Offline Python preprocessing, extraction, fitted scoring and causal score monitoring work. Deployment latency, hardware/power and new dashboard integration remain unvalidated. |
| Q16 | What transfers across motors, ratings, sensors and conditions? What requires recalibration? | Open. Journal faults occur on a modified 7.5 HP machine with no matching healthy recording in this subset. |

The research questions derive from the IEEE TIM-26-07983 technical review and the reconstruction discussion. Grammar and publishing administration are outside this register.

## Load-only experiment update — 6 November 2026
Q06/Q07/Q09: HP-specific models deferred. A shared healthy reference and load-centred reference with shared covariance both evaluated; no HP-specific score or threshold routing. Filename load metadata is still required for load-centred scoring. Q10/Q12: global event thresholds plus fixed EWMA/persistence give 0/17 sustained healthy alerts in short checks, with isolated threshold crossings; per-load thresholds add 2/17 or 3/17 without extra fault detections. Q11: 24 calibration episodes originate from 17 shared acquisitions; no independent acquisition validation. Q14: load centring has not demonstrated benefit over pooled reference on this comparison. Q15/Q16: longer continuous monitoring, transitions, deployment load metadata and independent acquisitions remain open. All 11 supported fault episodes alert in all arms; this does not establish subtle-fault sensitivity or unsupported-condition transfer. See load_experiment_results.md.


## Longer-monitoring update — 6 November 2026
Q10/Q12: continuing EWMA and persistence over full reserved check intervals reveals sustained false alerts in one healthy record for both A and C; A has two events, C one. Short calibration/check horizons do not establish a longer-horizon event rate. Q13: new smoothed alerts occur in Normal_1HP_0% at 263 s (both) and 295 s (A only); feature/channel and raw-signal diagnosis remains open. ## Normal_1HP_0% investigation — 6 November 2026
Q02/Q03/Q04: 15 native channels across target plus two controls passed missingness/padding/flat-second screening; 17,940 target feature values reproduced exactly. Physical units, sensor calibration and hardware synchrony remain unresolved. Q06/Q13: high torque crest factors and spectral centroid are present in the target's fit data, while vibration spectral shape changes later with stable amplitude; torque drives the largest positive score allocations. This does not establish degradation, a bad label or an HP-dependent cause. Q10/Q12: the 300-second-record calibration policy used only 30 decision windows from two short episodes; a continuous replay produces an event in the previously unused tail. Aligning calibration and monitoring horizons is the next supported experiment, not an already demonstrated fix. Q11/Q16: all evidence remains from exposed acquisitions; repeated independently identified recordings are needed. See normal_1hp0_investigation.md.
